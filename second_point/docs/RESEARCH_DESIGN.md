# 第二研究点设计（阶段 0/1 原设计，附阶段 2A–2G 状态）

## 2026-11-24 总体方向更新（后续设计，非实现声明）

硕士论文题目为《基于强化学习的错误报告缺陷检测》。第二研究点拟采用
AST 语义依赖分析、深层语义蜕变关系、编译前独立 Oracle、Contextual Bandit、
LLM 语义上下文与冷启动先验，以及缺陷导向联合奖励。
后续上下文由 AST 确定性事实与 LLM 高层语义特征共同构造；
Contextual Bandit 根据真实错误诊断反馈在线学习，联合奖励设计为
`R(t)=λD(t)+(1−λ)E(t)`，其中 D 为缺陷发现奖励，E 为语义探索奖励。
目标是发现更多不同的 Error Diagnostic Defects，不以测试成本、运行时间或吞吐率优化为目标。

阶段 2E 已打通位域 MR 的受限增强链路；阶段 2F 只评估固定 50 个原始种子的原生候选空间，
研究一种布局独立性证明并提取客观关系事实，见[阶段 2F 验收](STAGE2F_NATIVE_DEPENDENCY_VALIDATION.md)。
本次没有实现上述学习器、LLM 接入、特征编码器或奖励函数。
以下各节保留历史阶段的原始设计、阶段状态与当时建议，不能作为当前功能清单或新实验结果。

## 研究目标和基本流程

在 EDGM 已有种子、AST 和编译环境基础上，用语义依赖约束构造可解释测试，
以新的错误诊断缺陷候选及后续确认缺陷为主要产出。生成吞吐量和多样性是辅助指标。

合法候选 P0 → 双编译器重新验证 → 主文件 AST → 语义关系及可用位置 →
上下文策略选择种子/位置 → MR 变换 → P1 + 独立 Oracle →
GCC/Clang 严格检查 → 原始证据与结构化候选 → 学习反馈。
只有 P0、P1，没有 P2。双编译器接受 P0 是准入条件，不是标准合法性的完整证明。

独立性要求：Oracle 的语义结论来自 MR 前置条件、变换和可核验语言约束见证，
不得读取 GCC/Clang 错误消息来确定“应该报什么”。AST 前端是分析工具，不是被测诊断的真值来源；
未来需用受限类型模型/显式声明引用见证独立复核，避免仅凭一个 clang canonical type 作证明。

## 未来严格 Oracle 与诊断合同

每条 MR 必须包含：版本/语言模式、前置条件、选址见证、确定性变换、
相关语言约束的可靠出处、P0/P1 哈希及源位置映射、预期类别与精确字段、独立验证步骤和不适用原因。
必须区分语言要求产生诊断与研究框架预期的具体定位：不能预设标准要求在唯一列报错。
Oracle 要说明为何选择某个精确锚点；锚点不同先作为定位不匹配候选，经过人工分析才能讨论标准符合性。

默认仅 error/fatal；不纳入 warning，不加 ±1 行列、距离阈值、相似度或 unknown 通配。
对 Oracle 指定字段严格相等，要求字段存在且类别已识别。解析失败和 unknown 都不能算匹配。
不预设 GCC 与 Clang 必须给出相同数量的级联错误；未来需明确目标约束诊断及额外诊断的分别记录规则，
保留每条原始结果，不借用 EDGM 的子集放行比较器。
结果分为 match、diagnostic_mismatch_candidate、parse_failed、execution_failed、oracle_invalid 等，
confirmed_bug 只能经后续独立复核标记。本阶段尚无这些判定器。

## 预期强化学习接口

候选接口（设计）：`select(seed_contexts, site_contexts, valid_action_mask, rng) -> Decision`；
`observe(decision_id, outcome, cost, novelty_evidence) -> UpdateRecord`。
Decision 记录策略版本、特征版本、种子哈希、节点键、MR 候选 ID、可选动作、随机种子和选择概率。
Outcome 区分 MR 不适用、Oracle 无效、编译失败、解析失败、有效诊断候选和后续确认。

动作核心是种子和 AST 位置；初期固定一条已验证 MR，防止退化为算子 bandit。
先验证可提取的深度、节点类型、typedef 链层数、声明引用跨度、作用域距离、
控制流嵌套及历史有效反馈，再考虑离散/线性上下文 bandit 作为起点。
只有证明延迟决策/序列状态有必要，才引入更复杂 RL；不预先实现网络或调用外部模型。
特征缺失应显式标记，不用虚构 0；历史信息只来自过去决策，避免未来反馈泄露。

主奖励应围绕经过独立 Oracle 验证的、新的诊断缺陷候选，确认缺陷可作延迟反馈。
特征覆盖和成本可作辅助项，不能用嵌入多样性替代缺陷目标。
必须先冻结反馈定义及候选去重规则，避免奖励 unknown、解析失败或重复级联。
后续比较随机种子/位置、无上下文选择和上下文选择；保持 MR/预算/种子池一致。

## 下一条优先 MR 的建议（尚未实现）

优先研究“typedef 链—结构体函数指针成员—间接调用的按值结构体实参不兼容”。
候选 P0 包含经 typedef 链定义的回调参数类型、持有回调的结构体成员，以及合法间接调用。
选择具有已解析成员声明和参数依赖路径的调用位置，将该实参替换为当前作用域中另一种
不兼容结构体类型的已初始化对象表达式；保留标识符可见性、参数数量、其他类型关系和语法。
这避免仅交换两个粗类型类别，也不重复 EDGM 的 regex 注入函数重声明策略。

需要验证：两种不同结构体类型身份、链解析、成员引用和函数指针参数位置、表达式类型及可见性；
排除无原型/可变参数、宏生成调用、可疑初始化或其他约束违反。
Oracle 从参数赋值兼容约束及声明依赖见证推出目标违反，而不是从实际消息反推。
语言条款、定位策略和独立验证器在下一阶段先做小样例审查，再扩展到现有种子；
本次没有实现或声称验证这条 MR 的成功率。

## 阶段 2G 的路线更新

阶段 2A 已实现 typedef 间接结构体实参 MR，阶段 2E 已实现位域可取地址性 MR；
阶段 2F 固定 50 种子得到 0 个安全原生位域候选。阶段 2G 按用户要求改为主动合法结构准备，
不继续扩大原生扫描，也不把增强候选称为原生候选。

管线为 `原始 S → AST 上下文合法增强 P0 → 既有 MR 检查 → 独立 Oracle → P1 双编译验证`。
新增结构必须从原始初始化参数获取值，并把该值送回原计算。声明、地址、解引用或已知纯回调
形成可检查的 AST 身份关系；增强仅负责结构和局部值保持，不定义 Oracle 的目标错误。
正式 Oracle 分别复用 C11 6.5.3.2p1 和 6.5.2.2p2 的约束见证。

动作身份保留 seed/P0/MR/position/family/context_signature，规范化上下文不含随机名称、行列或种子哈希。
同一个 S 内按 MR+规范化上下文再次去重；不同 S 的动作仍是不同输入，不能因此声称具有不同结构族。
当前三族为同作用域单地址指针、嵌套作用域双地址指针、typedef 链和成员回调跨函数值传递。
精确规模、数据依赖证据、证明边界及诊断结果见 [2G 验收报告](STAGE2G_ACTIVE_SEMANTIC_ENRICHMENT.md)。

当前停止在阶段 2G。没有实现 DQN、MAB、Contextual Bandit、LLM、联合奖励或 const MR。
此前原生范围扩展建议被本次主动增强路线取代；后续 const 研究属于尚未授权实施的阶段 2H。
