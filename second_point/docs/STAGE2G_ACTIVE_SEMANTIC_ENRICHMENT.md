# 阶段 2G：主动合法增强与有效候选空间

本阶段从固定 50 个 S 主动构造合法 P0，复用两条已有 MR；不把增强称为原生候选或独立创新。
基准为 `6a515737d558fdffeb1c130b29fa3575ae42f433`，开始时本地与 GitHub main 一致。
阶段 2F 的 0 安全原生位域候选作为背景，本次没有重复两轮原生扫描，也没有实现 const MR。

计数来源：[enrichment_summary.json](../evidence/stage2g/enrichment_summary.json)、
[candidate_pool.json](../evidence/stage2g/candidate_pool.json)、
[semantic_contexts.json](../evidence/stage2g/semantic_contexts.json)。

| 指标 | 实测 |
|---|---:|
| 固定原始 S / 正常完成扫描 | 50 / 50 |
| 可增强原始读取位置 | 346 |
| 实际生成 P0 / 双编译合法 / 正式 MR 可用 | 237 / 237 / 237 |
| 同 S 同 MR 同规范化上下文重复项 | 1，保留证据、排除出动作池 |
| 去重后有效动作 / 覆盖 S | 236 / 50 |
| 位域 MR / typedef 间接实参 MR | 162 / 74 |
| 客观不同结构族 / 全局规范化上下文签名 | 3 / 74 |
| 有多个有效动作的 S | 50 |
| 普通原函数上下文 / main 控制上下文动作 | 128 / 108 |
| INT / UINT 输入动作 | 200 / 36 |

每个种子最多 6 个 P0，先按非 main、物理字节位置排序，每族最多选两个位置，第二个优先不同函数。
固定顺序遍历全部 50 个 S；没有重新挑选容易成功的原种子。346 个位置是枚举结果，
237 是有界物化结果，不宣称穷尽所有位置和组合。参数层面保守排除 908 个非普通 INT/UINT 参数、
173 个无法证明所有引用均只读的参数；这些是参数拒绝计数，不是失败 P0 数。
所有 237 次物化均成功：没有增强失败、P0 非法或 MR 不适用结果被隐藏。

动作身份包括 seed_id、P0_id、MR_id、position_id、enrichment_family、semantic_context_signature。
规范化签名只描述类型、原操作和祖先上下文、作用域、地址数量、访问和传播路径；不含生成名字、行列和 S 哈希。
正式 P1 编译前另按 `(S SHA256, MR_id, context_signature)` 取固定顺序首项，排除一个重复动作。
去重前池、摘要及上下文索引保留为 `*_before_semantic_dedup.json`；去重规则和时间在 `semantic_dedup.json`。
这比只用源码哈希去重更保守。不同 S 的相同上下文仍是不同测试输入，不能称为不同结构族。
每 S 的动作数分布为 19 个 S 各 3、7 个各 5、24 个各 6；全部拥有多动作。

## 三类结构及真实数据依赖

| 结构族 | 动作数 | 签名数 | 目标与依赖 |
|---|---:|---:|---|
| split_pointer | 81 | 29 | 局部 record/object 在入口初始化；另一语句取成员地址；原运算位置解引用。单地址，同作用域 |
| nested_two_addresses | 81 | 28 | 入口对象跨入新嵌套块；两条语句对同字段取地址；相等指针选择后解引用，回到原运算。双地址，跨作用域 |
| typedef_callback | 74 | 17 | 原参数初始化按值 record；三层 typedef；结构体函数指针成员调用已知纯辅助函数，取成员后返回原运算。跨函数值传递 |

例如真实选中路径：

- `seed_003/split_pointer_00`：原 `seed_0008_2017672589` 中 `func_62` 的 `p_64`，S 第 779 行第 105 列，作为既有函数实参计算的一部分。
- `seed_012/nested_two_addresses_00`：原 `seed_0047_1704664439` 中 `func_2` 的 `p_3`，S 第 348 行第 79 列，参与原按位与运算。
- `seed_021/typedef_callback_00`：原 `seed_0041_835489636` 中 `func_54` 的 `p_58`，S 第 1592 行第 397 列，经成员回调返回原实参计算。

目录前缀均为 `evidence/stage2g/enriched/`。每个 `formal_scan.json` 保存重新解析 P0 得到的
原参数声明、初始化读取、对象、原运算和替换表达式锚点及 USR；B 还保存纯辅助函数声明身份。
S 原始声明位置经 identity 段映射到 P0，初始化读取必须引用该声明；替换后原运算文本、节点种类及值类型必须对应。
三个结构族的输出都真实替代原读取，既有计算需要它们的值；B 不只是共享类型名字。

这比阶段 2D 的单个复合字面量具有明确的声明—使用分离和有限的跨作用域/跨函数路径，
但仍是有意构造的简单、闭合结构。不能把 236 个动作、74 个签名或复杂 Csmith 外壳解释为
236 种深层语义机制；实际结构族只有 3 类。108 个 main 动作仍属于基础控制上下文。
池中原上下文包括比较、按位/逻辑操作、返回值和经检查的普通函数实参；没有仅靠更名计数。

## S→P0 的证明子集与边界

新增 `active_enrichment.py`：只支持已初始化、非 const/volatile/atomic 的按值 int/unsigned int 参数，
且全部声明引用被 AST 证明为读取。拒绝赋值、自增、取参数地址、asm、相关宏、未求值上下文、
未初始化局部量等未证明情况。普通 CALL 入口排除 builtin；不处理任意表达式移动或副作用重排。
名字根据所有可见声明和宏集合避冲突，所有修改使用检查旧字节的精确编辑。

入口从不变参数捕获同类型值；新对象和指针均私有且初始化后才使用。A1 解引用地址保持相同值；
A2 的两指针指向同一活对象，比较及选择均有效；B 的辅助函数是经精确 AST/令牌检查的纯成员读取，
函数指针初始化指向该函数，无转换、未初始化成员或附加可观察副作用。
新嵌套块不能包入既有声明或标签/goto/case，不改变既有声明作用域或引入跳过初始化的入口。
自然对齐、宏和物理位置不满足证明条件时拒绝，不因两个编译器接受而替代语义依据。

证明的是：在原程序一次有定义的原读取求值中，送回既有操作的整数值和类型相同，
新通路不会引入已知额外 UB；不是全程序等价、全程序无 UB、资源行为或任意地址布局保持证明。
入口会提前进行一次无可观察副作用的非 volatile 参数读取，即使原分支之后不读取它；
不声称保持读取时刻/频次。真实 Csmith 程序仅做语法诊断检查，没有执行其二进制。
人工控制例在 INT_MIN、INT_MAX、-1、0、1 上分别以两编译器构建执行，6 次控制运行通过；不计入真实批量规模。

## 正式 MR 与独立 Oracle

标准依据为 [C11 公开草案 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：
6.5.3.2p1 的位域取地址限制、6.7.2.1 的位域类型和宽度、6.5.2.2p2 的有原型调用参数兼容约束；
局部初始化和值传递分别使用 6.7.9、6.5.2.2 的语义。标准的诊断义务不等于唯一消息标签或 caret 位置。

`controlled_bitfield.py` 是显式启用的 AST 证明子集，不依赖生成字段名字，不放宽旧原生检查器：
局部单成员记录、完整类型/对象/字段引用覆盖、1 或 2 个私有地址初始化指针、唯一受控解引用、
无布局观察/逃逸。正式位域 MR 仍通过字段声明身份关联所有原取地址表达式，仅编辑字段声明。
复用阶段 2E 的整数模型：当前双方 int 为 32 位、CHAR_BIT=8；使用合法完整 32 位 signed/unsigned int 位域，
声明宽度独立证明，不使用 `int : 1`。完整值域避免无关截断，1 或 2 个目标地址表达式保持不动。

typedef MR 继续使用阶段 2A 的符号边替换：修改实参专属 typedef 链中的依赖边，
使实参对象类型变为另一完整、不兼容结构体；成员回调形参保持原类型。
没有改成参数数量或语法错误。`controlled=True` 只新增已初始化普通 int 参数的单成员初始化证明，
以及相关区域的宏/属性/对齐/位置检查。默认旧零初始化与预处理限制保持；所有别名和类型使用闭合规则继续适用。

依据公开 [C11 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：
位域取地址违反 6.5.3.2p1，位域声明合法性检查涉及 6.7.2.1；不兼容结构体实参违反 6.5.2.2p2，
赋值相容关系涉及 6.5.16.1。合法增强使用 6.7.9 初始化、6.5.3.2 地址/解引用与 5.1.2.3 可观察行为模型。
标准要求对约束违反诊断，不规定本工具的唯一类别标签或 caret 列号。

`active_oracle.py` 以 P0 AST 和来源映射构造原正式 ConstraintWitness，再包裹 S/P0/P1 身份、
哈希、合法增强、完整双段 source_map、字段/结构体/typedef/函数/使用关系和局部值路径。
P1 字节从已证明编辑产生，不解析 P1，不使用其诊断构造见证。
每次运行依次写 P1.c、Oracle.json、`oracle_before_compilation.json`（Oracle SHA、重放结果和时刻），
之后才调用被测编译器；编译后再重放并核对 Oracle 哈希。
自动化测试同时禁止 subprocess 调用并限制所有解析到 P0，验证无需 P1 诊断即可得到 Oracle。
离线重放检查字节、身份事实和证明证书的一致性；哈希封存不是完整形式化 C11 证明，也不是防恶意伪造机制。

## 真实 P1 实验结果

精确数据记录在 [experiment/summary.json](../evidence/stage2g/experiment/summary.json)。
30 个真实候选全部生成 P1 并得到 `VALIDATED`，每族 10 个；GCC 与 Clang 各 30 次均为
`TARGET_ERRORS_OBSERVED`。每个编译器共有 40 个精确目标 error：单地址 10、双地址 20、
typedef 实参不兼容 10。无额外/unknown error，无位置差异、漏报、超时、崩溃、执行失败或 Oracle 失败。
诊断异常候选为 0，确认 bug 为 0。该结果验证受控链路，不是发现编译器缺陷或一般诊断完备性证明。

人工 3 个 P1 另行全部通过，每编译器 4 个目标 error；持久化 P1 总数为 33，真实结果只计 30。
全部 33 份 Oracle 在对应 P1 编译前落盘并重放，编译后 SHA 不变；
[artifact_replay.json](../evidence/stage2g/artifact_replay.json) 保存每项重放、原文一致性和物理文件核对。

编译前冻结 `selection_before_compilation.json`：每族从固定种子序列分层取 10 个不同 S，
族序号 i 将种子顺序轮转 i×10；同 S 按 position_id 排序取首项，不根据诊断换样本。
因此预选 30 动作来自 30 个 S，位域 20、typedef 10；普通函数 15、main 15，INT 28、UINT 2。
人工三个样例在 `manual/` 单独保存并排除真实规模。

环境固定 GCC 15.1.0、Clang 22.1.0、当前 libclang 18.1.3 和 Python 3.12.3；未安装/修改工具链或 runtime。
P0/P1 均用 `-std=c11 -fsyntax-only -w -I <原 runtime>`。P0 的两次返回码必须 0。
`active_validation.py` 仅实现必要的局部目标检查：已知 error/fatal 类别、精确文件/行/字节列和全部目标数；
未知、未解析 error、无关 error、缺失目标或位置差异均不通过。超时、崩溃（含驱动 ICE）和执行失败单列。
没有 ±1、模糊匹配、warning 代替 error、Werror 或完整比较引擎。
位置差异只形成待复核候选，不直接认定违反标准或编译器 bug。

## 证据、回归与复现

- `selection.json`、`source_snapshots/`、`source_snapshot_index.json`：50 个原始 S 的顺序、原路径、SHA 与各一份精确副本。原种子不改写。
- `enriched/seed_NNN/positions.json`：全部枚举位置和参数拒绝原因；各结构族子目录保存 P0、增强记录、S→P0 diff、双编译回执、正式扫描和结果。worker 超时/错误也有独立字段。
- `candidate_pool.json`：全部尝试、236 个有效动作、1 个语义重复排除项；`semantic_contexts.json` 保存 74 个规范化描述和有效/排除索引。
- `experiment/action_NNN/`：P1、独立 Oracle、编译前封存、P0→P1 diff、两编译器原始 stderr/stdout、命令/返回码/时间、严格结构化诊断和结果。
- `manual/`：3 个正例及 6 次控制执行。负例和禁止编译器反推 Oracle 的测试在 `tests/test_stage2g_active.py`。
- `baseline_all_tests.txt`：改动前 125 项通过；`final_all_tests.txt`：原 125 项与新增 16 项，共 141 项通过（16.388 秒）。中间日志另行保留。
- `artifact_replay.json`、`historical_witness_replay.json`、`audit_summary.json`：所有 P0 来源及保存 Oracle 的离线重放、旧阶段见证兼容。
- `readonly_check.json`：基准跟踪文件和 50 个原种子 SHA 的保护核对；开始时已有的 res/测试二进制删除与 backups/ 保留，不纳入提交。
- `environment.json`、`integer_profile.json`、`run_commands.json`、`implementation_manifest.json`、`implementation.diff`：固定环境、完整位宽、入口命令和实现快照。

复现命令见 [README](../README.md#阶段-2g主动合法增强和有效动作池)。输出使用独占创建，不能覆盖历史结果。

宏/未求值/可变/逃逸拒绝、双地址覆盖、来源/身份篡改、语义去重、未知诊断和 ICE 分离。

## 验收回答

1. **合法增强多少原始 S？** 50/50；实际 237 个 P0 均双编译合法，非原地修改。
2. **两种 MR 的有效动作？** 去重后位域 162、typedef 74，合计 236；全部 Enriched。本阶段没有重跑完整原生扫描，原生 0 是阶段 2F 的既有结果。
3. **结构族多少？** 3：单地址同作用域、双地址嵌套作用域、typedef 成员回调跨函数值传递；规范化签名 74，不等于 74 个结构族。
4. **多动作 S？** 全部 50 个，每个有 3–6 个去重有效动作。
5. **实际 P1？** 30 个真实动作，来自 30 个 S；另有 3 个人工 P1。没有按诊断重试或补选。
6. **目标诊断？** 两编译器各 30/30 通过，每方 40 个精确目标 error；人工结果单计。
7. **额外错误、误判和未覆盖依赖？** 实测无额外 error、诊断复核项或执行异常；有限子集之外仍拒绝。未声称覆盖别名逃逸、任意布局、宏生成路径、任意副作用、全局 UB 或全局等价。
8. **数据依赖强度？** 所有增强都把同一原参数值送回原运算；128 动作位于普通原函数，B 具有已知辅助函数的真实值回传。仍是三个简单受控增强族，不以复杂源码外壳宣传深层语义复杂性。
9. **Oracle 独立性？** 33/33 在 P1 编译前落盘并重放，编译后哈希不变；禁止编译/P1 解析测试通过，预期不来自 P1 诊断。
10. **能否支持后续 AST 上下文选择？** 50 S 的 236 个动作和 74 个规范化上下文具备身份、原 AST 位置、作用域和传播特征，可用于工程实验；本次成功率不是选择策略有效性证据，没有实现学习或证明统计充分性。
11. **是否值得扩展？** 值得先按族审阅误报和选择基线，评估增强偏差；不应立即宣称泛化到任意 C 程序或真实缺陷发现。
12. **回归和保护？** 基准 125/125、最终 141/141；237 个 P0 来源、33 个新见证和 6 个历史见证重放、只读保护全部通过。第一研究点、原始 S、旧证据、工具链和 runtime 未更改。

## 停止边界

236 个受控动作足以启动后续 AST 上下文选择的工程实验，但不代表原生适用性、正式实验统计充分性、
自然分布或已发现缺陷的多样性。后续值得先审查三个结构族的上下文覆盖及误报，再决定扩大范围；
应单独评估人工增强偏差，避免学习器仅学会族标签。合法增强是实验基础设施，不作为额外研究创新。
本阶段不实现 DQN、MAB、Contextual Bandit、LLM、联合奖励或第三条 MR。const 留待阶段 2H；完成本报告后停止。
