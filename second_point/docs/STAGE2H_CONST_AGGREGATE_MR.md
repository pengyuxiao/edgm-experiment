# 阶段 2H：const 聚合可修改性与初始语义测试空间

基准：`45775d50667412e2ea71ff862b39fbfeb78ee3d6`。本地/远端 main 开始时一致。
本阶段新增第三条 `MR_MEMBER_CONST_AGGREGATE_WRITE`，主动构造与原计算相连的合法 P0，
并完整执行阶段 2G 的 236 个有效动作及本阶段全部去重有效动作。所有真实候选均为 Enriched。
没有重复原生适用性审计，没有实现第四条 MR、Bandit、LLM 或奖励函数。

## 标准推导与证明边界

实际核对 [C11 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
及其[全文镜像](https://www.sigbus.info/n1570)：WG14 PDF 本次访问超时，镜像是同一委员会草案文本，
不是依据任务描述反推规则。核对记录在 `evidence/stage2h/standard_review.json`。

| 条款 | 独立推导用途 |
|---|---|
| 6.3.2.1p1 | 判断结构体左值可修改性时，递归考虑包含的聚合/联合体成员和元素的 const 限定 |
| 6.5.16p2 | 赋值运算的左操作数必须可修改；本 MR 的目标约束 |
| 6.5.16.1p1 | 简单结构体赋值同时要求兼容类型；本 MR 保持双方同一记录声明身份 |
| 6.7.9p11、p13、p16–p20 | 成员初始化按去限定后的标量类型检查，初始化列表按成员/嵌套顺序初始化；合法初始化不是对既有对象的赋值 |
| 5.1.1.3p1 | 约束违反需产生诊断，但不规定本实验的 error 严重性标签、唯一消息或 caret 列号 |

标准规定的至少一条诊断义务不等于每个违反点必须各有一条 error。
逐点覆盖和精确坐标是本项目更严格的研究合同；漏点或位置差异先保留为待复核候选，不能仅据此确认违反 C11。

P0 的叶字段为普通、非位域、无 const/volatile 的 int 或 unsigned int。唯一正式编辑是给字段声明增加 `const `。
成员声明和全部初始化仍合法。记录类型身份没有替换，因此 RHS/LHS 的记录兼容性保持；
但 LHS 的记录包含该 const 成员，沿真实包含边传播后不再满足可修改左值条件，违反 6.5.16p2。
预期类别固定为 `aggregate_not_modifiable_due_to_const_member`，语言约束不依赖实际编译输出。

支持范围是函数内私有、完整结构体和单个普通整型叶字段；直接路径或一层 Outer→Inner 包含边。
Outer 可以有额外的普通 int 标签字段，初始化为 0 且无其他引用。不支持任意递归深度、数组成员、联合体、
字段指针、跨函数别名、宏生成声明或不闭合原生记录。不能将有限事实重放器称为完整 C11 验证器。

## 主动增强及真实依赖

`aggregate_enrichment.py` 复用阶段 2G 的参数定位、名称避冲突、精确字节编辑和来源映射。
仍只接受所有引用均已证明只读、按值初始化、非 volatile/atomic 的普通 int/unsigned int 参数。
每个 S 每族最多两个位置，按非 main/字节偏移排序，第二个优先不同函数；第一位置生成一次整体赋值，
第二位置生成两次，目标数差异纳入规范化签名，不将名字/行号/哈希变化称为新结构族。

两类通路都是：原参数→源记录初始化→已初始化目标记录的整体复制→目标成员读取→原操作。
直接族从 dst.value 读取；嵌套族从 dst.payload.value 读取。成员值真实替换既有原始读取，
没有独立未使用的测试函数。两次私有同值复制不增加外部可观察副作用，但产生两个正式目标赋值点。
初始化和赋值分属不同 AST 节点，所有新增对象在使用前初始化，复制位于函数入口并支配成员读取。

必须区分数据路径与不可消去的运行时依赖：双赋值变体的首条同值存储可以被后条覆盖。
这类变体仅检验两个静态约束违反点的覆盖，不声称两条复制各自都是必要的数据依赖。
100 个单赋值动作可单列为基础通路，另外 62 个是多目标覆盖变体；二者都不是新的结构族。
嵌套族指类型包含而非新词法作用域；元数据 cross_scope=False 指模板不引入新作用域，
并不否认原操作可能位于既有内层块。后续更细作用域特征尚未编码。

局部依据：参数值在函数内不变，同类型成员初始化无截断，完整记录复制保持该成员值，最终读取类型相同。
原运算和分支执行位置保留；入口会提前捕获一个非 volatile 的纯读取，不声称保持读取频次/时刻。
不证明任意 Csmith 程序全局无 UB、全局地址布局或资源行为保持。真实原种子不执行二进制，人工控制另计。

## 重新解析 P0 的正式检查

`mr_member_const_aggregate_write.py` 不识别生成器前缀或固定字段名称。根据 AST 声明身份：

- 确认叶 FieldDecl、其普通基本类型和无 const 属性，独立检查完整记录声明/成员令牌语法。
- 沿 TYPE_REF 和真实记录字段类型建立 Outer→Inner 包含边；不用 typedef 名称或类型字符串代替声明身份。
- 闭合记录类型引用：仅两个自动对象，或先经唯一外层包含边再到两个自动对象。
- 验证源参数初始化、零初始化和记录兼容身份；完整收集源对象全部 RHS 使用与目标对象全部 LHS/成员读取。
- 所有整体赋值必须是同记录身份的裸 dst=src，支持 1–4 个目标；增强器只生成 1 或 2 个。
- 验证记录/对象/复制在入口依次建立、字段读取全部只读；拒绝直接写字段、地址/布局逃逸、额外 TYPE_REF、相关宏、属性和未证明对齐。

证明针对完整可接受使用集合，不能只保存第一个赋值。重新解析的源参数声明经 S→P0 identity 段
绑定回原声明；增强后的原操作和成员读取也必须相连。若自然存在多个结构候选，增强准备阶段保守要求
唯一且与原值路径匹配，不按生成名字选择。

## Oracle、诊断合同与人工验证

新见证采用独立 schema `stage2h-const-aggregate-v1`，保存 MR/约束、S/P0/P1 SHA、合法增强与 S→P0 map、
字段和记录声明、限定符前后状态、真实包含边、初始化、对象和成员使用、所有赋值及精确锚点、
闭合事实、P0→P1 字节编辑和偏移映射。新旧见证通过统一批次入口分别调用对应纯重放器。

执行顺序固定：P0 双编译准入→仅解析 P0 构建 Oracle/P1 字节→保存 P1 和 Oracle→重放→保存编译前屏障
（Oracle SHA 和时间）→编译 P1→保存原始与结构化诊断→再次重放并核对 Oracle SHA。
测试同时禁止 subprocess 和 P1 AST 解析，仍能生成与重放新见证。封存和重放检验源码/事实一致性，
不是外部防篡改机制，也不是任意 C11 语义的形式化证明。

`aggregate_validation.py` 是固定版本所需的局部识别和三 MR 的必要统一摘要，不是完整比较引擎。
const 类别映射在人工夹具验证前固定为 GCC 的 read-only variable 赋值错误、Clang 的直接/嵌套 const data member 错误；
精确保留文件、物理行/字节列、严重性、消息、类别和覆盖点。LHS 起始与 `=` 是独立、预先存在的精确 token 锚点；
不做邻列容忍或相似消息匹配。实际人工 GCC/Clang 均在 `=` 报错。标准不要求唯一 caret。
unknown/未解析/无关 error、类别、位置和覆盖差异均不通过；编译器超时、驱动 ICE、执行失败、worker 失败和 Oracle 无效分开。
异常动作以同一环境/相同 P1 再编译一次，保存两次证据；仅诊断状态和结构化记录稳定的异常进入稳定候选计数。
不自动认定 bug，不提交外部报告。

人工目录 `manual/` 有直接/嵌套各 1 次及 2 次整体赋值，共 4 个 P1；8 次编译观测均符合预期，
每个编译器 6 个目标 error，另 8 次 INT_MIN/INT_MAX/-1/0/1 控制执行通过，人工数量不计真实实验。
单元反例覆盖初始化与纯读取、同名不同身份、既有 const、不可修改 P0、直接字段写入、地址/sizeof/type 逃逸、
宏、篡改见证/包含边/位置映射、重复/未知/移列诊断和 ICE。完整原 141 项回归先运行并保存基准日志。

## 14 项验收回答

1. **第三条 MR？** 已实现，只给已有普通字段增加 const，保留远端整体赋值；没有用直接字段赋值错误替代。
2. **直接/递归传播？** 两类均已验证，递归子集限定为一层真实 Outer→Inner 包含边，不宣称任意深度。
3. **标准与独立 Oracle？** 已核对 N1570；基于 P0 AST、类型身份和精确编辑推出目标，禁止 subprocess/P1 AST 的测试通过。
4. **成功增强 S？** 固定 50/50，顺序和 SHA 沿用 2G/2B，没有重新筛选原种子。
5. **新增空间？** 162 个合法 P0、162 个去重有效动作、2 类结构、70 个规范化签名；100 单点、62 多点控制均明确分列。
6. **合并空间？** 位域 162、typedef 74、const 162，共 398；5 结构族、144 签名。不同源码哈希不等于不同结构机制。
7. **实际 P1？** 398 个不同真实 P1，全部执行；人工另 4 个，历史输入不重复计数。
8. **实际诊断？** 两编译器各 398/398 符合 Oracle；每方位域 243、typedef 74、const 224，共 541 个精确目标 error。
9. **异常与稳定候选？** 0 / 0；确认 bug 0，无外部 bug report。
10. **额外 error / Oracle / 执行失败？** 均为 0，未将任何失败当成正常无异常结果。
11. **编译前生成和重放？** 本阶段 402/402 份先落盘、重放再编译，之后 SHA 不变；全部通过最终纯重放，另 33 份历史 2G 见证也通过。

13. **保护？** 50 原种子、历史证据、第一研究点、既有 MR 代码及工具链/runtime 不变；用户原有工作区改动保留。
