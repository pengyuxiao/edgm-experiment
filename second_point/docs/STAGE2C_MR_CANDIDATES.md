# 阶段 2C：下一条深层语义 MR 候选设计

本文件是设计与筛选，**没有正式实现以下任一 MR，没有新P1或新Oracle执行结果**。
数据来自同一批50个合法种子的完整AST画像，见 `STAGE2C_SEMANTIC_PROFILE.md`。
三条设计的完整前置条件候选数、MR适用率均为 **未知/null**，不能用结构覆盖率替代。

## 1. 数据驱动的筛选结果

调查但不推荐进入下一步的方向：

- **命名常量/枚举→数组界限**：数组虽有5,780个，界限声明引用为0。
  没有现成跨声明常量依赖可修改；不得为建立关系添加固定枚举/数组模板。相关约束6.7.6.2 p1仍有研究价值，
  但该库不能支持它作为优先候选。直接把索引改越界多为UB/可选warning，不能保证严格error。
- **主文件typedef→实际表达式类型**：1,301个别名主要是EDGM添加的链，实际运算传播为0，
  不重复阶段2A“有链却没目标语义结构”的失配。
- **嵌套switch归属/转换碰撞**：当前嵌套为0，468个switch各有case0/1及default；
  直接复制标签与旧EDGM重合。观察到switch不能推算新的安全碰撞MR适用率。

## 2. 共同的标准依据与研究边界

条款参考公开的 [WG14 C11 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：

| 条款 | 本设计需要的规则 |
|---|---|
| 6.5.3.2 p1 | 普通对象取地址不允许位域 |
| 6.7.2.1 p4–p5 | 位域宽度与基本类型须合法 |
| 6.5.2.2 p2 | 有原型调用的实参需满足形参赋值约束 |
| 6.5.16.1 p1 | 指针赋值有兼容性/限定符条件 |
| 6.7.3 p10、6.7.6.1 p2 | 限定类型与指针兼容性按类型层级处理 |
| 6.3.2.1 p1、6.5.16 p2 | 含const成员的聚合不可修改；赋值左侧须可修改 |
| 5.1.1.3 p1 | 标准规定诊断义务，不指定统一严重性或唯一caret |

本项目的验收合同仍要求目标相关 **error/fatal**，warning不能通过。
独立Oracle应先根据声明、类型和变换证明目标违反，再执行目标编译器验证其实际表现；
标准约束违反不自动等于已确认编译器缺陷。当前没有为新设计建立消息类别映射或比较器。

源位置必须在P1 bytes上重新计算；完整保留声明与目标表达式的准确锚点、诊断原文和字段，
无±1、相似度或unknown放行。标准不强制唯一caret，位置不匹配先保留为候选供后续分析。

## 3. 候选一：MR_MEMBER_BITFIELD_ADDRESSABILITY

### 目标、位置与变换

沿已有的 `FieldDecl → MemberRefExpr → UnaryOperator(&)` 声明引用链，
将现有普通成员变成**本身合法的位域**，保持远端成员访问和取地址表达式不变。

设计示意，不是已生成的真实P1：

```diff
-    int member;
+    int member : 1;
```

其他位置原有的 `&object.member`、`&pointer->member` 或嵌套成员链保持。
不删除成员、不破坏标点，不添加新的非法成员/测试函数。
唯一非法性来自成员的可取地址属性随声明变化，影响到远端原始表达式。

### 完整前置条件（尚未实现验证器）

1. P0合法；目标FieldDecl位于主文件完整struct/union中，原先不是位域。
2. 独立类型模型确认基本类型为_Bool/signed int/unsigned int及允许的限定版本，
   不是依据`int32_t`等名字猜测，也不借用实现定义的long/char位域支持。
3. 独立证明选定宽度1合法；目标为单独、可精确定位的成员声明器，非宏、非匿名/多声明器歧义。
4. 至少一个原始 `&` 的真实操作数是引用该FieldDecl的成员lvalue。
   不把同名字段、不同记录身份或`&*E`的特殊抵消规则混在一起。
5. 收集该成员和包含记录的全部相关使用，包括所有地址表达式、sizeof/offsetof/布局约束、
   初始化、外部声明与宏映射。排除会产生其他约束违反的情况，或事先逐条给出独立见证。
6. 变换只改变一个成员声明器；所有预期报错地址表达式和源映射闭合，不能只保留首个地址点。

### P1必然违规的条件证明与Oracle

若以上条件成立：FieldDecl的新位域声明合法；原地址表达式仍解析到同一字段，
但操作数已经是位域lvalue，目标违反取地址约束。
推导不需要编译消息，也不依赖某个对象运行时实际指向哪里：成员的静态声明身份即可决定地址属性。

未来Oracle需保存：字段/记录USR、P0普通成员事实、规范基本类型与合法宽度证明、
成员引用链、全部取地址节点、排除的额外上下文、P0/P1哈希及精确source_map。
目标研究类别可为address_of_bitfield；只有实际error/fatal才满足执行合同。
本阶段没有创建这些新MR的ConstraintWitness对象。

### 实际结构与风险

相关结构为19种子、2,410次地址关系。可追溯例子：
`seed_0004_1594631173.c` 中 `c:@U@U1@FI@f1`，声明37:13，取地址133:43，规范类型INT。
这是已观察到的声明关系，不是安全变异证明。

尤其不能把全部2,410次当候选：部分成员类型是record、long或其他不在首版子集的类型；
同一字段可能还用于sizeof、宏或多处初始化。JSON中只有有界代表样例，
样例内类型直方图不代表全量地址边的类型分布。

完整前置条件候选数：**未知**。额外风险：合法窄位域会改变布局/整数提升/截断行为，
可能触及其他约束；sizeof位域会形成另一种error，需要排除或单独证明。
未闭合这些使用前，不生成P1。

### 与EDGM的本质差异及RL特征

`insert_invalid_bitfield_width_adv.py` 实际是在现有成员后插入 `int __edgm_badbf : -1`，
目标是新声明自身的非法宽度。这里宽度必须合法，改变的是**原有字段的地址属性**，
错误发生在经声明身份关联的远端地址表达式。
`field_delete`、struct_type_mismatch针对成员存在性/基对象类型，均不等于这个地址属性约束。
创新不应仅表述为“使用AST代替正则”，而是合法声明变化→远端约束失效及完整独立见证。

后续上下文特征：字段基本类型、记录/嵌套层数、地址引用数、声明—使用跨度、
指针/点/箭头访问路径、其他使用上下文数、宏位置可靠性、宽度证明复杂度。

## 4. 候选二：MR_MEMBER_CONST_AGGREGATE_WRITE

### 目标、精确位置与变换

选择有原始整体赋值 `record_lvalue = compatible_record_expr` 的完整记录类型，
给它的一个现有可编辑叶成员加const，保持聚合对象声明和远端整体赋值不变。
可沿已有记录包含关系递归推广，但不能预设当前所有整体赋值都有嵌套记录路径。

设计示意：

```diff
-    int member;
+    const int member;
```

原来的 `a = b`、`*pointer = b` 或数组元素整体赋值不改。
本MR不通过把整个变量声明直接改成const来制造局部写错误。

### 完整前置条件（未验证）

1. P0整体赋值合法、左侧原先可修改，记录及字段身份明确，定义与使用都在可验证范围。
2. 叶成员原先不为const；独立模型证明修改后成员声明/初始化合法，记录没有未处理的匿名/联合覆盖或宏问题。
3. 所有包含该叶类型的记录路径已解析，确实连接到目标赋值的左侧类型。
   “同一种子既有嵌套记录又有赋值”不够，必须按记录身份连接。
4. 收集该类型所有整体赋值和目标成员的直接写入，排除非预期错误，或预先为全部相关违反出具精确见证。
5. 函数参数/返回、对象初始化、限定符和外部定义没有额外未验证的影响，不依靠编译器反推这些事实。

### 独立证明与Oracle

在条件成立时，记录声明仍为同一类型，兼容性并未因为名字变化而改变。
但它含有const成员，整体对象的可修改性消失；保留的赋值左侧不再满足modifiable lvalue约束。
该性质可沿包含记录递归传播；普通读、初始化与参数传值应分别分析，不能当成普通赋值左侧一概判错。

未来Oracle保存叶成员/包含记录身份图、限定符变化、左值类型和路径、全部写入位置及影响闭合，
推导目标为aggregate_not_modifiable_due_to_const_member。
此推导与修改成员类型名字、删除成员或直接加const到目标变量不同。

### 实际结构、风险和比较

记录类型到整体赋值为10种子、59次；例如 `seed_0004_1594631173.c` 的U0定义29:7，
741:70处存在其数组元素整体赋值。叶成员选择和其他写入尚未验证，完整候选数 **未知**。

记录包含关系只有3条；仅 `seed_0048_1326245496` 同时包含这种关系和整体赋值。
其代表包含路径S1→S0和代表赋值类型S2并不相同，不能把共现算成已连接的递归候选。
因此首版可以先研究直接成员→整体赋值的跨节点影响，递归推广仍为未知。

主要风险：成员直接写入造成额外诊断、某个父记录本就不可修改、
错误地将函数初始化/传值当成赋值操作、宏与未处理外部类型使用。

EDGM的add_const主要针对变量/指针/被指对象并保留相应名字写入；这里改变的是类型内部成员，
影响远端整体聚合左值，即使对象本身表面类型没有const也不再可赋值。
底层仍属于可修改左值约束家族，不能把这点隐藏；创新在类型内部属性的跨记录/使用点传播及独立影响见证。

RL特征：成员限定层、包含路径深度、整体赋值数及跨度、左值形态、成员写入数、
相关类型实例数、初始化/外部使用负担和独立证明是否闭合。

## 5. 候选三（暂淘汰）：MR_DEEP_QUALIFIER_CALL_INVARIANCE

### 目标、位置与变换

研究普通函数原型与多级指针实际参数的限定符不变性，避免再次制造函数声明/定义冲突。
首版设计只选择已有调用 `f(&p)`，其中 `p` 是局部 `T *`，形参调整后为兼容的 `T **`。
在p的类型说明符中加深层const，使p为`const T *`；函数声明、定义、实参表达式保持。

设计示意，不是实际样本P1：

```diff
-    T *p = &object;
+    const T *p = &object;
     f(&p); /* 原有调用不改 */
```

### 完整前置条件（未验证）

1. P0合法，普通函数的原型/定义身份和形参位置确定；应用函数参数调整后比较类型。
2. T限于独立模型支持的相同基本类型，或者有可靠声明身份的相同类型；
   不用类型名字不同判断不兼容。
3. 实参确实是已有的 `&p`，不是任意T**表达式；p是可编辑主文件局部指针声明，
   原始层级、限定符和初始化清楚，不含函数指针、数组或void特例。
4. p的初始化/直接赋值在加入const后仍合法；pointee无需要写入的其他使用。
5. p的地址不在其他初始化/赋值/返回等位置逃逸，或这些位置全部具有已验证的同类目标见证。
   不能把“曾有q=&p”当成足以证明q在调用处仍绑定p。
6. 所有可能受影响别名、写入和调用闭合，不引入之前的初始化不兼容或只报warning的其他变化。

### 独立约束证明与Oracle

在这些条件下，P0的`&p`为T**；P1的`&p`为const T**。
单层T*到const T*的允许转换，不能直接推广为T**到const T**的兼容性。
按限定符所在层递归比较，T*与const T*不能在下一层简单视为兼容的同类型指针，
原函数的T**形参赋值条件因而失效。
这不是“出现const就错”，也不是靠两条类型字符串不相等推断。

未来Oracle记录函数/形参身份、参数调整结果、p声明、&表达式、限定符类型树、
初始化兼容性推导、地址逃逸/写入排除见证和新调用锚点。
目标为nested_pointer_qualification_incompatible_argument，实际执行必须是目标error/fatal。
收尾检查发现本地Clang 22.1.0源码的C分支使用ExtWarn，因此不能给出当前合同所需的error依据。
本设计在当前约束下暂淘汰，不安排正式实现。

### 实际结构与风险

相关结构为10种子、70对深度至少2的形实参。
例如 `seed_0004_1594631173.c` 中函数func_45的形参1770:52与1568:391的实参相联，
原代码的实参为 `&l_931`。其余使用和潜在写入未完成闭合，所以不是已确认候选。
70对关系也可能包含传递T**变量而非`&局部p`的情况，不能整体纳入首版。

完整候选数：**未知**。主要风险是pointee本来就被写入、其他`&p`会先引起初始化error、
强制转换隐藏真实类型差异、参数调整/限定符层级混淆，以及把warning当目标error。

### 与EDGM区别及RL特征

`insert_param_type_conflict` 改定义里的形参而保留原型，主要制造跨声明冲突；
`swap_call_args_mismatch` 根据粗类型类别交换实参；本设计二者均保持。
`add_const_keep_writes_adv` 的pointee_const模式与本设计共享“增加const”的编辑原语，
但旧代码基于名字统计写入并优先保留写入，目标是不可写约束；
本设计要排除这些写入，目标是**指针下一层兼容性与地址逃逸的调用约束**。
因此有原语重合，不能夸称毫无相似；独立性需要由精确关系、目标约束和闭合Oracle体现。

RL特征：实际/形式指针深度和限定符路径、实参形态、声明—调用跨度、作用域距离、
地址逃逸数、其他写入数、原型/定义数量、初始化兼容性证明状态。

### 严重性策略否决依据

本地 `toolchains/src/llvm-project-22.1.0.src/clang/lib/Sema/SemaExpr.cpp:17409`
对IncompatibleNestedPointerQualifiers在C模式选择ext_nested_pointer_qualifier_mismatch；
`include/clang/Basic/DiagnosticSemaKinds.td:9212` 将它定义为ExtWarn。C++分支的Error不能用于本项目C11实验。
这与简单的不兼容指针类型Error分类不同；固定-w下不能靠warning满足目标。
源码路径与SHA256保存于 `evidence/stage2c/diagnostic_policy_review.json`。
这是静态源码策略审查，未生成/编译本设计P1，也没有伪造已安装二进制的实际stderr。
即使将来实测存在不同分支，也必须重新验证严格error前提，当前不计适用。
编译器策略仅用于筛选实验合同可执行性；语言约束与未来语义Oracle仍须独立推导。

## 6. 为什么优先候选一

1. 它已经有19种子/2,410条真实关系作入口，且有规范基本类型INT/UINT的可追溯样例。
   此处只说明结构入口存在，不预测实际适用率。
2. 目标是清楚的静态地址属性约束，不需要先做全程序运行时别名分析，
   也不依赖CsmithEdge目前不生成的回调结构或未被使用的主文件typedef链。
3. 与EDGM“插入非法位域宽度”有明确的语言约束差异：声明本身保持合法，
   远端原有取地址失效。它比单纯更换语法或算子选择更能体现第二点的跨节点语义方法。
4. 最大未知项明确：可编辑基本类型子集和全使用闭合，下一步应先验证这些，而不是马上生成大量P1或训练。

建议的下一阶段验证顺序只是计划：先建立只读完整前置条件检查，得到真实安全字段数量，
再以极小正/负例验证合法位域与远端地址约束、生成独立见证，最后最多少量真实样本验证error。
如果完整检查仍为零，必须保留零结果，再评估第二候选；第三候选在当前合同下不应实施，不补模板伪造适用。

## 7. 对强化学习和方法创新的实际启示

可用的上下文来自真实关系，而不是只有AST种类计数：

- 节点身份、语法/作用域/类型路径深度、声明—使用跨度。
- 一个变换可能影响多少地址点、调用点或整体写入；类型属性传播范围。
- 字段基本类型、指针层级及每层限定符、实参形态、记录包含结构。
- 宏映射可靠性、独立证明覆盖度、额外错误风险、MR前置条件拒绝原因。
- 后续历史反馈必须区分解析失败、不适用、Oracle未闭合、目标error候选与人工确认缺陷。

本阶段没有实现这些RL状态或策略。空动作集不能靠强化学习变成有效候选，
结构覆盖率也不能作为诊断缺陷收益。

与第一篇EDGM相比，第二点可主张的方法创新应是：
**选取已有程序中的语义依赖子图，以合法声明属性变化控制远端语言约束失效，
变换前闭合影响范围并同步构造独立见证，再由AST上下文选择有价值的种子/位置。**
不是“将原算子改名”“用AST包装正则”“给现有TS加几个计数”，也不能把尚未实现的RL或已确认缺陷作为本阶段成果。
地址属性、聚合可修改性和被否决的深层类型兼容性，是三个不同的条件证明方向；
当前只推荐前两个，第三个因严重性策略暂淘汰。本阶段证明它们有真实相关结构并给出待验证设计，**没有证明任何一条已具有高MR适用率**。
